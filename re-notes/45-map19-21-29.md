## MAP-21 My Documents

- `tP1L.getUsageMyCloud` (~18846952) makes GET to the media-cloud domain
  `/cloudmedia/info/pc/v1/usage-mycloud` with ordinary common params and no
  mutation payload. Domain accessor (~17997445) falls back to the existing
  `endpoints.rs` zcloud service.
- `tP1L.getCloudViewerKey` (~18847200) makes GET on authDomain
  `/api/getCloudViewerKey`; decoded result supplies `viewer_key` and `enk`.
  The existing fork file-viewer POST helper is not used for quota.
- `tP1L.N` (~18844500) passes `cloud-viewer-key` as a header. Response data
  decrypts with this dedicated cloud `enk`, not the session key. Module `98yS`
  (~3605976) base64-decodes the key and response, takes the first 16 response
  bytes as IV, and decrypts the remaining bytes with AES-CBC/PKCS7.
- Usage service `qwfD` (~18210684) reads `quota`, `usage`, and
  `service_usage.my_cloud`. Free-plan usage uses the explicit my_cloud count
  where supplied; no local cache estimate is substituted for server quota.
- Right-sidebar cloud section (~11117171) renders the usage chart and a
  `STR_CLOUD_REVIEW_AND_CLEAN_UP(_MYCLOUD)` action. The action calls
  `loadMyCloudMessagesInBackground()` and navigates to management. It does not
  execute an unconfirmed blanket deletion. The fork opens the actual media
  inventory with explicit per-selection delete confirmation instead.
- Fork deviation: no paid-plan purchase UI, guessed quota default, automatic
  credential refresh loop or zCloud reset mutation is introduced. Read errors
  retain an explicit unknown/error state. Quota is refreshed on request.
